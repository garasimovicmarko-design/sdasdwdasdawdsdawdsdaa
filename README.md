# SK ADAMAS — сайт спортивного клубу

Повноцінний сайт спортивного клубу «SK ADAMAS» (тхеквондо, кікбоксинг ISKA) у
Івано-Франківську: публічна частина + адмін-панель + API + база даних.

> **Важливо:** цей проєкт було зібрано в середовищі без доступу до мережі, тому
> `npm install`, міграції бази даних та production build ще **не запускалися і
> не перевірялися**. Перед деплоєм обов'язково пройдіть кроки нижче локально і
> виправте будь-які помилки, які виявить лінтер/компілятор — вони цілком
> можливі у проєкті такого розміру, зібраному без проміжного запуску.

## 1. Стек технологій

- **Frontend:** Next.js 14 (App Router), TypeScript, Tailwind CSS
- **Backend:** Next.js Route Handlers (REST API)
- **База даних:** PostgreSQL
- **ORM:** Prisma
- **Валідація:** Zod (client + server)
- **Форми:** React Hook Form + Zod
- **Карти:** Leaflet + OpenStreetMap (без платного API-ключа)
- **Auth:** сесії на cookie (iron-session) + bcrypt для паролів
- **Тести:** Vitest (unit), Playwright (E2E)

## 2. Встановлення

```bash
# 1. Встановити залежності
npm install

# 2. Підняти локальний Postgres через Docker
docker compose up -d

# 3. Скопіювати .env.example у .env і заповнити значення
cp .env.example .env
# AUTH_SECRET — згенеруйте: openssl rand -base64 32
# SEED_ADMIN_PASSWORD — придумайте надійний пароль для першого адміна

# 4. Застосувати міграції
npm run db:migrate

# 5. Заповнити базу початковими даними (19 філій, тренери, напрямки)
npm run db:seed

# 6. Запустити сайт у режимі розробки
npm run dev
```

Сайт буде доступний на http://localhost:3000
Адмін-панель — http://localhost:3000/admin/login

## 3. Змінні середовища (.env)

| Змінна | Опис |
|---|---|
| `DATABASE_URL` | Рядок підключення до PostgreSQL |
| `AUTH_SECRET` | Секрет для шифрування сесії адміна (32+ символів) |
| `NEXT_PUBLIC_SITE_URL` | Публічна адреса сайту (для SEO/sitemap) |
| `NEXT_PUBLIC_MAP_PROVIDER` | Наразі підтримується лише `osm` |
| `INSTAGRAM_URL` | Посилання на Instagram клубу |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | Дані першого адміна, використовуються лише під час `db:seed` |

Ніколи не комітьте `.env` у git — лише `.env.example`.

## 4. База даних

```bash
npm run db:migrate        # застосувати міграції в розробці
npm run db:migrate:deploy # застосувати міграції в production
npm run db:seed           # заповнити початковими даними
npm run db:studio         # відкрити Prisma Studio (візуальний перегляд БД)
```

Seed-скрипт (`prisma/seed.ts`) містить усі **19 реальних філій** клубу з
адресами, телефонами та тренерами, а також 2 напрямки (тхеквондо, кікбоксинг
ISKA) і фотографії клубу з наданих матеріалів.

### Як додати 20-ту (і наступні) філії

Через адмін-панель: **Admin → Філії → форма «Додати філію»**. Вручну редагувати
seed-файл для цього не потрібно — форма створює запис одразу в базі даних.

## 5. Розробка

```bash
npm run dev        # dev-сервер
npm run lint        # ESLint
npm run typecheck   # перевірка типів TypeScript
npm run test         # unit-тести (Vitest)
npm run e2e          # E2E-тести (Playwright, потребує запущеного dev-сервера)
```

## 6. Production build і деплой

```bash
npm run build
npm run start
```

Рекомендований деплой: будь-яка платформа, що підтримує Next.js
(Vercel, Railway, Render, VPS з Node.js) + керований PostgreSQL
(Neon, Supabase, Railway Postgres, або власний сервер).

Перед першим запуском у production:
1. Встановіть усі змінні середовища з `.env.example`.
2. Виконайте `npm run db:migrate:deploy`.
3. Виконайте `npm run db:seed` **один раз** (повторний запуск безпечний —
   `upsert` не дублює довідники, але створює нові філії з `create`, тож не
   запускайте seed повторно на продакшн-базі, де адміністратор вже додав свої
   філії вручну — це задублює 19 стартових локацій).

## 7. Вхід в адмін-панель

URL: `/admin/login`
Логін/пароль — ті, що ви вказали у `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`
перед виконанням `npm run db:seed`.

Якщо потрібно створити додаткового адміністратора пізніше, найпростіше —
через Prisma Studio (`npm run db:studio`): створити запис у таблиці `Admin` з
хешем пароля, згенерованим через bcrypt (12 раундів). Окремий UI для
управління адміністраторами свідомо не реалізовано в першій версії з міркувань
безпеки — додавання нових адмінів має бути свідомою дією розробника/власника
проєкту.

## 8. Як змінити контент

- **Розклад:** Admin → (розділ Розкладу — API готовий, UI для розкладу ще
  потрібно доробити, наразі керується через Prisma Studio: таблиця `Schedule`)
- **Філії:** Admin → Філії — повний CRUD через UI
- **Заявки:** Admin → Заявки — зміна статусу, нотатки, видалення
- **Тексти сторінок «Про клуб», hero-заголовок:** таблиця `SiteSettings`
  (наразі редагується через Prisma Studio; окрема сторінка «Налаштування» в
  адмінці — у списку залишкових задач нижче)
- **Зображення:** додайте файли у `public/images/` і вкажіть шлях
  (`/images/файл.png`) у відповідному полі бази даних, або завантажте через
  Prisma Studio до появи окремого UI для завантаження файлів

## 9. Що вже реалізовано

- Повна схема бази даних (Prisma) з усіма сутностями та зв'язками
- Seed з реальними 19 філіями, 6 тренерами, 2 напрямками, фото клубу
- REST API: locations, trainers, schedule, signup, news, reviews +
  захищені admin-ендпоінти (login/logout, stats, locations CRUD, signups)
- Автентифікація адміна: bcrypt, cookie-сесія, rate limiting, middleware-захист
- Публічні сторінки: головна, напрямки (+2 окремі сторінки напрямків), філії
  (список з фільтрами + карта Leaflet, детальна сторінка), розклад, тренери,
  про клуб, контакти, новини (+стаття), галерея, досягнення, відгуки
  (перегляд+форма), запис на тренування, політика конфіденційності, умови
  використання, 404, глобальна помилка (500)
- Адмін-панель: dashboard зі статистикою, CRUD філій, управління заявками
  (статус, нотатки, пошук/фільтр, видалення)
- SEO: динамічний sitemap.xml, robots.txt, метадані на кожній сторінці,
  Open Graph, структуровані дані SportsActivityLocation
- Docker Compose для Postgres, .env.example, докладний README
- Unit-тести (валідація форм, rate limiter) та 5 E2E-сценаріїв (Playwright)

## 10. Що залишилось доробити (реальний, чесний список)

1. **Запуск і перевірка** — весь код написано без доступу до мережі/БД, тому
   `npm install`, `db:migrate`, `db:seed`, `npm run build`, `npm run lint`,
   `npm run test`, `npm run e2e` потрібно виконати вручну і виправити помилки,
   які напевно знайдуться (типові речі: неточності версій пакетів, дрібні
   помилки типів).
2. **UI для розкладу в адмінці** — API вже готовий (`/api/admin/schedule` ще
   не створений — потрібно додати за аналогією з locations), форма створення
   тренувань з прив'язкою до філії/напрямку/тренера.
3. **UI для «Налаштувань сайту»** (SiteSettings) — редагування hero-тексту,
   тексту «Про клуб» через адмінку замість Prisma Studio.
4. **UI для управління тренерами та новинами** в адмінці (моделі й публічні
   сторінки вже є, форм створення/редагування в адмінці ще немає).
5. **Модерація відгуків в адмінці** — модель і публічна форма готові,
   екрана «Approve/Reject» в адмін-панелі ще немає.
6. **Завантаження файлів** — наразі зображення додаються шляхом (URL/path) до
   `public/images/`; повноцінний файл-аплоадер з перевіркою типу/розміру ще не
   реалізований.
7. **Переклади (RU/EN)** — архітектура готова (усі тексти зосереджені в
   компонентах/БД, легко винести в i18n-словники), але сам переклад не
   виконано — за завданням це не обов'язково для першої версії.
8. **Координати філій** — у seed-даних координати не заповнені (їх не було в
   вихідній інформації); карта на `/locations` покаже маркери лише після того,
   як адміністратор додасть latitude/longitude через форму редагування філії.
9. **Реальні фото філій та тренерів** — наразі використано лише загальні фото
   клубу з наданих матеріалів; фото конкретних залів/тренерів потрібно додати
   окремо.
10. **Конкретні досягнення** (імена, кількість медалей, місця змагань) —
    свідомо не вигадані; сторінка `/achievements` містить лише те, що видно
    на наданих фотографіях, і повідомляє, що детальні дані додасть
    адміністрація.

## 11. Дані, використані в seed
